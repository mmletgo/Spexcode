## raw source

大型同步应由多个分区完整读取对应源码并写对应Spec，完整性由分区并集证明；不能要求每个模型读取全仓，也不能放宽预算、独审或最终验证。

## expanded spec

复用 [[sync-partitioning]] 的唯一计划与既有runner/store/checkpoint，按固定小批并行各区分析、P1及补丁准备；取消或异常后不派新工作，已在途任务先结算。真实native容量及原子预算不改变，不另建SQL队列、子operation或自定义持久任务表。

分区analyze/P1保存原件；聚合拒重复变更ID、目标路径、新归属和resolution写者及冲突事实来源。真实changedPaths必须由分区唯一覆盖。上层raw作为只读context；raw-only根仅在自身没有源码writer且存在真实后代子实现目标时先完成一次`interface_seed`独立语义审查，父节点只生成必要REQ/RULE/GAP接口并保持raw/code/related，不得冒称完整P1。随后子区用冻结`validationScope: partition_local`只读该接口并按真实codePath归属；没有真实后代目标的缺实现叶继续受原readonly_implementation_gap门禁。P1后沿真实契约引用完成最终分区依赖覆盖，保持原partition身份和原分析引用。

分区分析的新增事实归属复用唯一writer计划：factSourcePaths精确取本区非Spec writePaths，不受code_to_spec的实现只读模式清空。共享只读oracle与依赖继续全文读取并在change.evidence举证，不由多个分区各造同source异文的typed fact；既有可信事实仍按原source/text核验。聚合的同来源冲突拒绝保持，不拼接、改名或丢弃事实来制造通过。

生成区只返回本区完整文件补丁，核实际读取、scope、局部Spec目标和独立oracle后统一确定序装配。生命周期历史正文按本区旧owner投影；其精确code、related目录或glob通过[[code-anchor]]共享路径匹配器在各自旧manifest entry上展开，不复制未命中的全仓文件。唯一publication/CAS接缝只冻结一棵candidate。每个局部/跨边独审重新读取对应完整最终正文，全部绑定同一candidateDigest并与全部builder身份独立；聚合保存原review，不生成全仓模型accept。code_to_spec仅装配已审Spec，核source/tests Git对象逐字、mode及absence不变，不运行可写代码生成器。V1–V4及单journal/receipt仍由 [[sync-coordinator]] 完成。

所有局部阶段键含partitionId，完成后持久refs，重入复用真实已完成结果。异步完成顺序不影响最终树；相同文件多writer或业务ID冲突拒绝，不按最后完成者覆盖。


code_to_spec 的 P1 实现写范围显式为空；分区投影保留该只读约束，不把各区代码 writer 误传成允许补写源码或测试的权限。
没有既有源码writer且非纯父级的功能分区，先经同runner/预算执行一次implementation_plan，只列精确源码/测试路径，不写正文或产生业务批准。完整局部已审契约和实际读取全文仍冻结；程序核原global授权、普通精确文件、已有文件须本区完整读取、Spec只读和外部oracle。所有提案返回后核跨区实际文件writer互斥，冲突作为具体repair沿原attempt/修复预算自动重规划，不降成人工业务GAP，也不把global目录复制给每区。

通过的file-writer-plan同attempt持久，新增路径通过原scope扩充动作取得精确租约及null基线，并在同内容树上重绑readSet，再进入generating。新实现路径只授予对应区；局部和跨边最终独审完整读取实际新增源码。文件规划不另加业务独审：原P1义务、最终候选V2及V1–V4继续审业务。动态阶段在P1揭示实际义务后，精确核尚未派发的文件规划/生成/分区及跨边独审调用与原预算族剩余量；已完成调用不重扣。原计划、文件计划及真实最终覆盖集合分别保留，不把blocked或未独审分区列成已覆盖。


完成依赖闭包仅增加完整契约接口上下文，不把只读dependency owner的全部code/test再次复制进每区。本区owner的完整源码/测试保持；跨边审查显式以两端为实现目标，最终V2以真实owner与边原件分别证明覆盖。所有P1分区完成后，使用同一完整final-candidate检查器把合并契约绑定到冻结全局文件并完成seal；FLOW直接引用其适用的上游REQ，AC明确covers上游义务，源代码与测试覆盖由真实子owner证明。多层纯父时，叶FLOW.req与AC.covers直接列出本叶实际承接的全部祖先REQ，不能仅靠可传递的depends-on满足直接FLOW覆盖。`readyIds`、`readyFlowIds`和父义务覆盖只从这次全局seal投影，不能并集局部checkedIds或把只读context当作writer。父接口拆分为多个独立REQ时，每条跨边只检查其两端真正引用的契约ID，不把兄弟REQ并进edge checkedIds。P2跳过无源码writer的纯接口父节点本地生成/复审，由真实子owner和跨边界审查覆盖其义务；不派发全仓代码输入或伪造全局模型accept。


P1新批准的code/AC.test路径在最终分区中只交给真实owner，且必须与原全局写授权相交并排除只读oracle；related仍只读。操作P1 scope扩充实际取得租约后，生成输入再与真实readyScope求交，不因详细Spec提及路径而产生新全局写权。


P1后新增路径若令两个生成区争用同一文件或父子路径，在文件布局/代码生成的任何模型派发之前返回implementation_plan_conflict规划repair；不默许最后写者覆盖，也不等双补丁生成后才归终态unsupported。code_to_spec不追加实现写路径。共享新增文件需要先形成唯一文件writer规划，冲突状态不能被列为已同步。


生成的有效Spec写集合再限于本区targets、真实新增叶及本区生命周期旧新路径；读取上游接口或全局scope可写不能令只读上游Spec成为本区writer。越界Spec补丁在候选scope/CAS前拒绝且不进入独审。
