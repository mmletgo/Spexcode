P1物理草稿观察所需的当前binding、含只读祖先/诊断overlay的StageWorktree及inputDigest，沿既有loadElaborationDraftMaterial仅作进程内参数传递；不进入持久请求/计划或改变缓存摘要。loadDraft认证Git来源与existingDraft传入同材料回调，只有已认证严格更新attempt/round的物理稿可替换；合法candidate/续审、分区owner/plan/schema和原source/test保护不变，未批准physical材料仍须真实新提交及独审。

P0分析从原完整 compositionEvidenceBlob 读取真实冲突；每区的本次分析路径仅由原触发路径与精确source/写者/target文件角色派生，shared read不授owner。原partition-plan、digest和expectedPaths不追补；新局部输入经既有freeze/inputDigest接缝绑定实际集合，已saved accept亦须完整摘要相同，不能直接绕过新指导。新analysis的coverage及局部原件引用记录真实分析路径，所有旧分析/请求/CAS原件保持。最终合并在原完整全局冲突集合上核每个路径恰有一个owner，并要求真实已独审finding（conflict/coverage_gap）或合法resolution逐项覆盖；缺任一条、foreign路径或归属不唯一均拒绝，不合成一次全局模型accept。

分区P1把本轮实际业务schema摘要传给同一草稿/材料来源回调，仅作进程内选源参数；plan、owner和schema均匹配才能接续正式retryOf祖先原稿，不继承祖先的ready或accept，当前唯一计划和最终strict seal保持。

P1后置分类质疑按原partitionId及局部analysisRef投影给唯一P0 owner，受影响的当前saved分析也不能绕过新inputDigest；其它分区不收到兄弟诊断，继续按原完整输入承接已审P0。新局部独审形成新聚合ref后，P1保持原全局analysisRef binding、global mode、祖先接口与跨区语义输入，按完整新绑定重审，不为缓存命中削减输入或补写旧binding。原operation/fence及预算、唯一计划与最终全图seal不变。

P0分区续修复用唯一analyzeCodeBehavior接缝及[[sync-code-behavior]]草稿协议；每区continuation独立checkpoint，完整计划和局部inputDigest均匹配才加载。原 JSON 草稿、失败状态与已校验 analysis trace 跨 attempt 保留。review 格式失败只重开对应 review，业务返修只引用同区经认证的真实独审原件，已批准兄弟结果继续复用。旧只读Native材料通过同一按区key及精确schema/input读取接缝迁接，不与Git草稿混淆；失败并集、真实changedPaths、完整独审与最终验证门保持。

partition_seal返修复用原generationRef/acceptedRef核验真实失败并集与本owner已审原件，包括具体error、真实owner和本区完整changes；派生诊断副本与临时duplicate更名资格，不新增持久字段或写授权。生成和独审均取得同一小型路径/ref/error任务及只读诊断seed；独审副本替回本轮本区候选。失败并集不覆盖真实作者.spec，避免只改草稿的正常提交被既有全局错误阻塞；原targets/sourceDigest、源码/tests对象、absence和草稿单文件范围保持。局部接受前沿同一严格图验证本区可修旧error及新增跨owner错误，最终仍由全分区并集strict seal决定是否推进；旧accept不因拥有同一诊断目录而跨当前完整输入承接。

失败并集返修和最终strict seal共用既有真实composed补全的sealInput.files；该不依赖结果的装配在派发前完成，partitionSealFiles只通过进程内elaborate参数交程序替回门，新建Map后覆盖原失败并集与本区候选，不改变局部targets/context/files、唯一freeze摘要、prompt或checkpoint。仅已认证纯父interface_seed的原已有、确由真实后代补齐的流程/验收/实现声明完成性错误可由full后代继续处理，父仍须新生成及独审；父条款自身的真实代码来源缺席不得交叶代修或先获父独审；原可修结构错误、任何新增跨owner错误及full owner未消除的assigned错误仍在独审前拒绝。已冻结范围中的真实缺源码/测试继续拒绝，全部局部后仍执行原最终strict seal，不从局部接受投影全局通过。

普通与readonlyRepair的saved/accepted实际返回点共同调用草稿缓存核验，readonly结果使用对应readonlyRepairInput。当前完整局部输入、真实Git/ref/schema/owner/source及最终已审正文→候选绑定都须成立；source-tag来源于原attempt，不由当前新input补签legacy。历史失败draft只核身份，不把其坏JSON当成最终成功schema。whole重放仍通过同一局部路径及全局strict seal；合法命中不重开模型。

该缓存核验同时返回当前local owner范围的复用资格。saved/accepted仅因scope失效时，不返回旧ready、不篡改其历史批准或抛stale中止；沿原loadDraft优先或已冷验缓存的末轮精确Git稿续修并重新独审。普通及readonlyRepair四个返回点遵守同一资格，兄弟global affectedIds不能替代本区analysis。JSON/schema/身份及原ref保持，损坏原件仍走原错误门禁。

P1分区按owner传递[[sync-elaboration]]的草稿引用与具体错误。可续草稿和可复用accept使用不同checkpoint接缝：草稿跨父接口或完整局部inputDigest变化仅提供非权威字节，接受缓存继续要求完整局部inputDigest及原partitionBinding精确匹配，当前局部缓存摘要失配同样拒绝。当前source、已审祖先及所有原raw/授权/只读代码测试门重新生效；兄弟草稿不进入本owner写范围。只有新生成、程序检查、独立read审查及最终strict seal通过后才能形成业务候选。

当前native-worktree各区仍共用原partition、operation/fence/budget、唯一writer计划与最终candidate。P0、P1接口/叶、精确implementation_plan及所有独审均可自由读完整仓库；readPaths/files只是任务上下文和责任投影，不能作为FS读取授权或既有文件不可改门。P1已审祖先overlay与P2全局已审Spec overlay形成真实seed，不因局部files省略而落回live HEAD。文件规划只返回原全局授权内的精确owned写路径；P2编辑工作树真实commit差量由[[sync-generation]]导入原preparedChanges，再经唯一writer/范围/CAS合成一棵candidate并分别按区和跨边独审其真实tree。独审checkedIds及授权范围仍局部，不能因可读取而扩大writer。code_to_spec始终specOnly、code_generate=0，全部源码/测试path/mode/OID/absence保护不变。旧无标记操作保下文frozen历史接缝。

同operation多轮继续使用同一partition计划与checkpoint：分析在原code-behavior唯一冻结context摘要接缝查询已审局部原件，普通叶P1在真实localInput完成后沿原freezeElaborationInput查询；协调器核完整原stage/readSet/selection/plan/分区及独审绑定，保原resultRef和traces并以当前fence登记fromAttempt。已有纯父承接保持；新的局部承接不覆盖聚合全图seal，每次合并仍核全部目标/ID/依赖覆盖，不缓存P2候选批准。

正式 retryOf 的局部 P0 批准查询使用当前完整业务摘要、原冻结分区计划、实际 changedPaths 和分析 schema 摘要。通过认证的原结果按原 resultRef 和 traces 进入完整聚合，并沿原操作认证只分析资格及后续验收。

只读返修将完整局部输入摘要传给 [[sync-coordinator]] 以选择 Git 续稿。启用已冻结的文件级来源路径时，优先复验同任务的已批准旧输入；需要新 schema 时，同任务旧 Git 失败稿沿原绑定读取并作为未批准材料续修。

只读装配late V1锚点诊断只进入精确owner的localInput与唯一冻结摘要：沿原已审局部正文和JSON重新生成及独审，不能当作失败业务seed或事实/授权。其它区不附诊断、不改变targets/context摘要，继续承接原已审ref与traces。当前/历史缓存均不得绕过受影响owner；新局部通过仍重做最终全候选seal与V1。只读候选的有效独审repair使用同一ReadonlySpecRepair容器并标识candidate_review来源，仅相应owner接收原review诊断与候选JSON；以原冻结作者目标和files为演进基准，未交付生成正文不成为新授权，其他owner正文与ref保持。P2的Spec写权限投影只来自真实dispatch的allowedScope与readonlyContractPaths，纯父和其它不可写目标不因同operation另有writable owner而取得P2 writer；投影不改变原权限。

分析的每个分区执行、来源读取、归属校验及checkpoint保存错误均保留原code/message与partitionId，聚合等待全部在途任务结算后保所有失败及原主错误。完整proposal/review仍在原诊断message中，不按首错丢失其它分区失败。下一attempt诊断按原失败分区路由，只有同operation且完整计划/readSet/selection相同的已终结来源可供修复；其它区的诊断不能进入本区冻结上下文。

复用 [[sync-partitioning]] 的唯一计划与既有runner/store/checkpoint，按固定小批并行各区分析、P1及补丁准备；取消或异常后不派新工作，已在途任务先结算。真实native容量及原子预算不改变，不另建SQL队列、子operation或自定义持久任务表。

原生P1分区因周期进程观测失败结束并正式结算后，同一operation的后续attempt将P1限制为一次一个在途分区。即使另一分区的普通失败是聚合主错误，仍在当轮失败摘要记录调度标记，保留原主错误与原件引用。冻结并发上限、模型、预算及停止证明保持原约束；原稿、局部独审、最终封口和验证沿原流程。仅有结构化输出或业务校验失败时继续按原上限调度。

同一小批调度在每个处理单元结束后以setImmediate真正让出事件循环，缓存立即Promise、最后一项和失败边界也不例外，使既有心跳timer与暂停/取消控制可运行。让步后仍按原停止/取消状态决定是否派下一项；结果顺序、在途上限及原失败身份保持，不延长租约、心跳周期或调用预算，不放宽fence。

同一轮的封口返修分区等待共享的历史来源核验。查询在历史原件之间让出事件循环，核验完成并确认当前fence后才使用来源准备分区请求。

分区analyze/P1保存原件；聚合拒重复变更ID、目标路径、新归属和resolution写者及冲突事实来源。真实changedPaths必须由分区唯一覆盖。上层raw作为只读context；纯父分类复用 [[sync-partitioning]] 的唯一`rawOnlyInterfaceSeedEvidence`，从真实ElaborationInput构造最小分类输入并消费冻结phase，不伪造完整协调plan。首次raw-only及既有非空且业务只含REQ/RULE/GAP、可附精确可信VERIFY的纯父，仅在真实raw非空、自身没有源码writer且存在真实后代子实现目标时，按祖先层级先完成`interface_seed`独立语义审查；同层独立纯父可并行，后代纯父读取已审祖先接口并以自己的真实raw为局部intent，所有seed结算后才并行非seed叶。父节点只生成或维护必要REQ/RULE/GAP接口并保持raw/code/related，不得冒称完整P1；重复已完成树或保存父raw仍走同一阶段，旧接口及稳定ID保留，删除仅允许已核验的逐项retire，完整旧新演进和最终seal不放宽。局部seed保留冻结可信VERIFY登记以核对既有只读完整祖先的AC/VERIFY，既有精确可信VERIFY可原样保留，不授予seed新增AC/VERIFY或测试写权。子区用冻结`validationScope: partition_local`只读已审接口并按真实codePath归属；没有真实后代目标的缺实现叶继续受原readonly_implementation_gap门禁。已独审analysis.newNodes可为初始无seed的纯父提供后验依据：真实后代Spec路径与codePath必须精确归属唯一source partition，不能以测试、related或无关活跃源码充当子实现；真实新增叶只加入该source partition。原plan.digest、parent partitionId、analysis.ref和classifier evidence进入局部inputDigest与结果原件，checkpoint复用须保持同一绑定。P1后沿真实契约引用完成最终分区依赖覆盖，保持原partition身份和原分析引用。

分区分析的新增事实归属优先复用显式source role：plan声明sourcePaths时，factSourcePaths精确取本区sourcePaths的非Spec部分，即使code_to_spec的本区writePaths为空也保留真实来源事实资格；历史计划缺sourcePaths时仍用本区非Spec writePaths。共享只读oracle与依赖继续全文读取并在change.evidence举证，不由多个分区各造同source异文的typed fact；既有可信事实仍按原source/text核验。聚合的同来源冲突拒绝保持，不拼接、改名或丢弃事实来制造通过。

v2 code_to_spec新增治理叶的父Spec目录授权仅从原全局writePaths与原global target、其在本区targets或contextNodeIds/readPaths中的可读范围相交后投影为authorizedParentSpecPaths；行为分析再核该路径对应当前冻结图中非空raw父Spec。该窄投影只允许在该父目录下创建由本区精确业务源码候选派生的Spec叶，不能回填或扩大本区writePaths，也不能授权源码、测试、未选父节点或其他分区。

生成区只返回本区完整文件补丁，核实际读取、scope、局部Spec目标和独立oracle后统一确定序装配。生命周期历史正文按本区旧owner投影；其精确code、related目录或glob通过[[code-anchor]]共享路径匹配器在各自旧manifest entry上展开，不复制未命中的全仓文件。唯一publication/CAS接缝只冻结一棵candidate。每个局部/跨边独审重新读取对应完整最终正文，全部绑定同一candidateDigest并与全部builder身份独立；聚合保存原review，不生成全仓模型accept。code_to_spec仅装配已审Spec，核source/tests Git对象逐字、mode及absence不变，不运行可写代码生成器。V1–V4及单journal/receipt仍由 [[sync-coordinator]] 完成。

所有局部阶段键含partitionId，完成后持久refs，重入复用真实已完成结果。跨attempt的已接受interface_seed和普通叶P1经协调器专用checkpoint入口承接：先用本轮targets、已审祖先context、files、授权、技术政策及完整partitionBinding构造真实localInput，复用elaboration唯一freezeElaborationInput接缝比较完整inputDigest；plan、analysisRef、descendants或任一输入不同均重新生成和独审。已接受原件进入本轮settledSources，原resultRef/review/traces保持；全局seal不由该入口复用，最终完整全图seal每轮重新执行。异步完成顺序不影响最终树；相同文件多writer或业务ID冲突拒绝，不按最后完成者覆盖。


code_to_spec 的 P1 实现写范围显式为空；分区投影保留该只读约束，不把各区代码 writer 误传成允许补写源码或测试的权限。
没有既有源码writer且非纯父级的功能分区，先经同runner/预算执行一次implementation_plan，只列精确源码/测试路径，不写正文或产生业务批准。完整局部已审契约和实际读取全文仍冻结；程序核原global授权、普通精确文件、已有文件须本区完整读取、Spec只读和外部oracle。所有提案返回后核跨区实际文件writer互斥，冲突作为具体repair沿原attempt/修复预算自动重规划，不降成人工业务GAP，也不把global目录复制给每区。

完成依赖闭包仅增加完整契约接口上下文，不把只读dependency owner的全部code/test再次复制进每区。本区owner的完整源码/测试保持；跨边审查显式以两端为实现目标，最终V2以真实owner与边原件分别证明覆盖。所有P1分区完成后，使用同一完整final-candidate检查器把合并契约绑定到冻结全局文件并完成seal；FLOW直接引用其适用的上游REQ，AC明确covers上游义务，源代码与测试覆盖由真实子owner证明。多层纯父时，叶FLOW.req与AC.covers直接列出本叶实际承接的全部祖先REQ，不能仅靠可传递的depends-on满足直接FLOW覆盖。`readyIds`、`readyFlowIds`和父义务覆盖只从这次全局seal投影，不能并集局部checkedIds或把只读context当作writer。父接口拆分为多个独立REQ时，每条跨边只检查其两端真正引用的契约ID，不把兄弟REQ并进edge checkedIds。P2预算和runner复用同一个`implementationPartitionSelection`：跳过无源码writer的纯接口父本地生成/复审，以及双端均为纯接口父的实现复审；普通无当前code且需文件规划的新叶仍保留。父接口依赖及P1独审原件继续保留，由真实子owner和实施跨边审查覆盖全部readyIds；最终覆盖只登记实际独审原件，不把跳过的父接口边冒称实施证据。不派发全仓代码输入或伪造全局模型accept。


P1新批准的code/AC.test路径在最终分区中只交给真实owner，且必须与原全局写授权相交并排除只读oracle；related仍只读。操作P1 scope扩充实际取得租约后，生成输入再与真实readyScope求交，不因详细Spec提及路径而产生新全局写权。


P1后新增路径若令两个生成区争用同一文件或父子路径，在文件布局/代码生成的任何模型派发之前返回implementation_plan_conflict规划repair；不默许最后写者覆盖，也不等双补丁生成后才归终态unsupported。code_to_spec不追加实现写路径。共享新增文件需要先形成唯一文件writer规划，冲突状态不能被列为已同步。


生成的有效Spec写集合再限于本区targets、真实新增叶及本区生命周期旧新路径；读取上游接口或全局scope可写不能令只读上游Spec成为本区writer。全局readyScope与局部写范围按路径覆盖关系求交，目录授权须收窄为本区合法文件，不能因全局使用目录而丢失本区精确Spec路径；更窄的全局范围仍保持。越界Spec补丁在候选scope/CAS前拒绝且不进入独审。

并行P1的同ID共享VERIFY登记只在全部局部结构及独审通过后、同一strict final seal之前做确定性唯一owner投影。仅接受id/argv/cwd/timeout全部符合冻结verifications的技术行，不增加模型调用或业务批准。独有ID保持原owner，即使命令相同也不合并不同ID；跨owner重复时优先保留原输入唯一真实physical owner，包括只读context；仅沿已冻结合法nodeChanges.move映射到其真实新路径，证据仍保存原路径及最终owner，退役或任意模型迁移不获得新归属。原输入已有多owner明确拒绝，不静默修复；新共享ID优先本轮真实可写intent target，否则按真实可写target路径确定序选择，不能造业务节点或改写只读Spec。仅本轮已独审候选的VERIFY技术表可变化，所有业务行、稳定ID、raw、说明、frontmatter及code/related/test绑定逐字保留；无法证明技术表以外字节不变则拒绝。不同定义或未登记行仍hard reject，业务duplicate-id及同source异文事实仍由原严格门禁拒绝。投影后的changes及candidateDigest继续接受同一完整权限/演进/严格全图检查，不借技术投影复用旧review冒称新业务批准。局部原件和原digest不改写，持久projection证据绑定plan、局部原件refs、注册定义digest、原owner/候选owner/最终owner以及每候选before/after源码SHA和非VERIFY源码SHA；同一输入可仅凭policy与原件重算，checkpoint重入零调用且投影稳定。后续同步父REQ/RULE/GAP加技术VERIFY仍为纯接口，普通富父不获豁免。

纯父合法update_verification复用原输入授权核验及完整契约演进：先验证本target既有ID的具体用户/可信裁决授权，再允许旧技术定义进入接口阶段，由程序从冻结登记提供该ID精确新行。模型VERIFY输出仍为零项，未授权或伪授权旧定义漂移继续拒绝；空changes及显式空行差量均不能绕过已授权技术更新。技术归属投影本身不授权政策变化，原独审与strict seal仍核更新后的完整候选。

局部结构或独审拒绝的续修沿同一checkpoint接缝取得对应partition已结算原candidate/output/findings/review/traces，在构造当前localInput后用唯一freezeElaborationInput核完整摘要及分区绑定，再把seed交既有elaborate/validateRepairSeed。父接口失败和多个叶失败都逐分区接续，保留具体诊断与原追踪，不能把partitioned_final聚合候选塞给某叶；当前原意、祖先context、readSet、selection或政策变化时不得沿用旧seed。seed仅为失败诊断，不跳过新的结构/独审及strict final seal，也不改变预算、oracle或写权。

只读待处理诊断仍只投影受影响owner；兄弟承接基准取当前最新合法已审whole，而非诊断产生时的旧兄弟ref。已通过同一诊断的新局部结果在兄弟失败后继续沿原完整输入摘要承接；新的合法aggregate承接证明须保留原generationRef及acceptedRef，不以空findings复审代替owner的新生成与独审。

最终候选的局部/跨边独审可承接同一operation中已结算attempt的严格accept原件：当前检查点优先；仅以旧requestKey重算唯一冻结摘要并核原完整请求、candidate、plan及来源绑定，全部一致才保留原ref/review/traces并在当前fence登记provenance。失败、repair及上下文改变不能复用；当前V1、真实全分区覆盖、独立性与最终交付门保持。


分区最终封口的程序校验上下文以协调器已验证的真实 composed 不可变树为基准，补入未参与本轮分区的既有只读承接节点及其真实源码/测试；不能把只读祖先的全部义务误要求由本轮局部叶重新承接。Agent 的 targets/context/files、完整读取证明和写范围保持原分区投影。已冻结局部读范围中的真实缺席不得从旧树补回；本轮完整候选的替换、新叶和冻结 move/retire 仍由原候选 overlay 在严格全图检查前执行，删除的旧节点不能继续提供覆盖。最终门继续检查完整图的真实引用、祖先义务、AC、代码与测试，不能过滤 projection missing 或关闭 strictContextCoverage；局部已审原件与摘要不改，最终 seal 摘要绑定补全后的实际程序图。
