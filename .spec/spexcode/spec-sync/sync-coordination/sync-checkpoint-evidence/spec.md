## raw source

结构化输出失败的原文必须完整可查并可续修，但不能被当作可信阶段或业务结果；真正损坏的阶段证据必须显式失败。

## expanded spec

含analysisOnlyPartitions的全局P1读取另核共同whole P0、同计划、每区精确原P0 ref/正文及两种分区证据的完整互斥并集，并用同一聚合算法重算新inputDigest。仅分析P0 ref保活为JSON证据，不作为P1 round或raw；原局部强认证继续仅沿partitionEvidence进行。

新SyncCheckpointRef在一次正常store动作中登记JSON wrapper与全部typed artifacts，保留原resultRef、JSON材料及精确UTF8 raw引用，避免中间出现无认证来源的raw pin。raw即使是合法JSON或形似sync-stage-v1也不取得stage、candidate、review或证据引用可达权限。

保活收集与应用证据BFS共用精确BlobRef形状：只含合法sha256的引用及带artifacts的SyncCheckpointRef扩展建立CAS边，扩展中的真实引用继续递归收集。内联字节包（如bytes/sha256/gzip）的摘要不建立独立CAS引用；其原字节、长度和SHA继续由原运输协议核验。真正引用的缺失或损坏仍显式失败，untrusted_final仍只沿精确原文/ref专门分支和原失败身份认证。

旧无role checkpoint引用逐字保留。只沿真实wrapper及失败Saved round（含既有repairDiagnostics原件）认证untrusted_final：原operation/attempt/input、owner及完整NativePlan/dispatch、资源原failed观察、canonical record的原策略/model/请求/错误/原文和thread/turn必须精确一致，CAS正文与SHA/ref相同。后续正式cancelled/removed保原格式错误与原文，且精确nativeStopped/stopped证明成立时仍可读；不复原旧failed或改签成功。generic failed的合法raw可读性不授予格式自动续修资格。

先收集认证结果再赋予JSON材料阶段权限；历史flat材料的解析错误只在精确强失败来源证明其为raw时豁免，任何未认证SyntaxError仍抛出，role本身不能隐藏坏材料。全部协调stage扫描与应用证据BFS共用该边界；raw只返回明确untrusted_final/text/SHA投影，不解析或追踪其正文中的伪引用。旧业务输入/授权/schema/只读范围与预算、调用、停止和交付门保持。

partitionEvidence容器中的rounds是原局部结果的副本，不能以聚合的inputDigest/failure替原owner认证。读取先核唯一partitionId与原local绑定、完整rounds按引用顺序精确拼接；全局partitioned_final重算同planDigest及各local输入摘要，早退单local容器保原binding/inputDigest。随后仅沿各原resultRef执行既有完整Native强认证；嵌套refinement.prior/repair-input沿同一机制，错ref、错输入、删改重排round或重复owner均显式失败。

同一原Native强认证接缝也供精确code_review格式续审的原result/plan/checkpoint引用读取复用，核原canonical record、请求/schema/prompt/模型、失败身份及停止状态；不新增raw role或平铺pin，不给旧缺席补ref，不解析原文取得stage、accept或业务权限。

同一store当前operation内可按commonDir与SHA复用纯JSON解码（包括语法拒绝），不得缓存stage、typed/raw或Native认证结论。每次扫描以传入的当前checkpointRefs建立独立读取快照，逐份重新读取并核CAS摘要；同次root/artifact/inspect共享已核字节与解码，下一次仍重新认证全部可达typed/失败来源、资源及canonical record。切换operation或commonDir清除纯解码作用域；返回独立对象，调用者修改不能污染后续扫描。当前refs改变、CAS损坏、role或原生状态变化仍按原门禁拒绝。

失败请求/dispatch/payload、原failed观察与canonical身份共用一个认证前缝，原文packet/SHA/CAS仍另核；Git材料不借raw权限。后续正式cancelled的原nativeStopped由真实provider回执解释，不硬编码provider的nativeStatus字符串。新Git材料分支另外要求removed checkpoint.stop与canonical cancellation的session/thread/turn/state、nativeStopped、acknowledged、nativeStatus和error原值完全一致；旧raw不因新增Git门槛被要求改签其历史checkpoint。

同一新Git材料观察接缝接受有原failed资源观察的canonical failed，或已正式cancelled的历史记录；两者均强核原完整绑定、removed及stop全字段一致。failed不得用allowStoppedDraft绕过原failed观察；cancelled允许原失败未被旧版观察，不回签旧failed。具体ZCode任务/原公开终态认证及材料选择仍由adapter/coordinator负责，该认证不授格式、raw、output、成功或自动重试。
