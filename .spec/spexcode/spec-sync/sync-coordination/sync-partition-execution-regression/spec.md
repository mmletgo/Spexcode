只读接口回归让A仅借读B完整Spec而不含B源码，核A checkedIds没有B业务项；最终A/B cross-edge同时完整读取两端源码，不能保留readonly skip或以局部checkedIds冒充跨边实现覆盖。

旧生命周期Spec的`related: [src/helpers/**/*.js]`在真实删除提交中命中根层`src/helpers/format.js`；生成和最终独立审查都收到同一旧快照里的helper完整首尾字节，且不把它伪装为current files。


P1新增AC.test的writer仅落本区并与原写授权求交：授权generated测试可继续实现，只读oracle及outside路径不获权；真实应用裁决沿原oracle政策互斥门禁继续验收。

真实v2 root-only raw规划经source discovery形成的targetless分区，以及已有code绑定但源码只读且无既有AC的目标，都必须在AC生成前通过planner取得全局授权的精确mandatory test正文与绑定；P1 Native输入冻结完整正文，已存在时只读AC通过存在性门。正文缺失或测试不在局部授权视图时仍拒绝为 `readonly_implementation_gap`，只读测试不获得事实来源、源码或写入授权。


两区争用同一新增测试文件时，生成返回规划repair、candidate为空且Native调用为0；既有布局冲突和全局越权/只读oracle反例保持。


夹具与真实规划器一样分别保存readPaths/writePaths数组，给分区增加只读上下文不能通过共享数组悄悄扩大写范围；只读Spec反例显式越界补丁仍必须在scope门禁拒绝。

三个分析分区共同读取同一真实oracle全文，Native输入在显式sourcePaths下精确冻结各自本区业务source role作为factSourcePaths，共享oracle不获事实归属；旧计划缺sourcePaths时保持writePaths发现语义。code_to_spec将本区writePaths置空后仍可引用本区只读源码事实，原global Spec目录授权只窄投影为本区可读的global target父Spec；该父可在本区contextNodeIds中仅作只读上下文，不能变成本地target/writer。即使当前executionScope仅有父`spec.md`，分析阶段也不提前扩scope，新增叶继续沿既有P1 lease扩展。不得复制全局路径到局部写集合。各区只提交自身源码事实并独审后，程序聚合保留三个不同来源原件，不触发共享测试的同源异文冲突；factSourcePaths不等于实现写权限。

raw-only父接口回归使用三节点Git夹具：只有无自身源码writer且存在真实后代源码target时，父先完成独立`interface_seed`，之后子区并行细化。多个可分离父REQ分别由适用叶子的FLOW/AC/code承接；无子目标或仅有目录外源码target时仍受原readonly实现缺口约束。子流程/验收/code/test缺口及全局context缺源码或测试都必须被final seal拒绝；补齐冻结文件后seal通过，局部partition_local上下文校验仍保持原范围。

双方向P2回归要求纯接口父Spec在spec_only装配和spec→code候选中都被程序保留，不产生父源码builder或父local review；父REQ继续出现在真实子owner与cross-edge requiredIds中，各边不强制检查兄弟REQ或读取兄弟实现。

多层纯父回归使用独立四节点真实Git夹具：根与中间父按祖先次序完成接口独审，中间父冻结自己的raw和已审祖先正文，之后两个源码叶同时在途。各叶FLOW.req/AC.covers直接承接适用各级REQ，所有父义务仅由严格全局seal推进；漏祖先直接承接或缺源/测试仍拒绝，原业务raw、源码和测试bytes不变。分类路径证据参与局部输入摘要和结果，不作为子源码正文读取。已独审newNodes可为初始无seed的中间父提供唯一真实后代，新增Spec只归实际source partition，未独审分析拒绝；仅测试治理的后代不能借无关sourcePaths获得seed。双向P2保留全部父接口并只派真实子owner构建与真实实施跨边独审，同一最终candidate不变。Mock拒绝没有实际叶源码的实现独审，纯父↔父依赖保留在plan而不派实施review；返回原件准确等于选出的实施边，全部readyIds仍由真实独审并集完整承接，普通无当前code的新叶不被筛掉。相同分类绑定的checkpoint重入零调用，改变plan digest或伪造无子实现的冻结seed则拒绝；newNodes的无owner和多owner同样拒绝。

已有完整sync-v1祖先加raw中间父的Git夹具核对冻结可信VERIFY登记继续存在：祖先既有AC/VERIFY必须按原登记校验，seed输出schema仍禁止自身新增VERIFY。清空登记的旧流程先失败，保留真实登记后逐级独审与全局seal通过。

双方向真实Git夹具核对最终派发投影按GenerationInput.readyIds筛选局部及跨边：两端各有独立ready不使全阻断边获得review，scope中的恢复node/VERIFY技术身份不增加调用。requiredKeys与注入runner的实际请求逐项相等；精确历史退役owner仍进入本地和跨边ready独审及预算，新叶的动态文件规划只扩读取/写路径，预算集合与实际全部规划/生成/独审保持相等。
