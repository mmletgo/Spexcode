# 跨冻结分区证据的独立影响复核

## raw source

旧分区原稿和已通过的独审可以节约重跑。当前冻结的变更即使处于旧分区读集之外，也可能改变调用、共享依赖、契约、配置或测试发现，须由本次独立复核判断影响。

## expanded spec

冷验沿原 Native 工作树恢复请求：逐项核对 Git 父提交、当前只读 seed 的全部 path、mode 和摘要，以及四类证据文件的原字节。冷验不生成新的阶段提交或 Git 引用。

使用 [[cross-freeze-binding]] 固定的旧操作及 [[cross-freeze-provenance]] 原件。调用者先按 [[sync-checkpoint-evidence]] 核对原分区候选和真实作者，适用时核对原批准和原独审。当前原生只读请求绑定当前操作、尝试、冻结输入和政策，旧操作、尝试、候选摘要和证据引用、原会话身份、owner、阶段、完整差量摘要，以及实际当前阶段和叠加证据后的 Git seed。请求在当前真实阶段树的私有只读文件提供两个冻结标识、前后 Git mode/OID、完整补丁、原候选及适用的原批准。证据正文只由工作树交付。

复核以冻结源码、调用方和共享依赖、契约、配置及实际测试发现为依据。逐个精确变化路径检查新增、删除、mode 与内容，写出可定位的事实、对本区义务的影响理由及 `reuse` 或 `affected`。全局 `reuse` 要求每条变化均明确适用，无法确认时填 `affected`。空差量也须显式复核双冻结、历史原件和当前分区义务，附具体依据。遗漏、重复、额外路径、错误 schema、错误摘要或缺少可验证结算时拒绝授权。

新审查会话、线程与回合须独立于原作者和原审查。授权所用结果绑定已认证的当前 Native 派发、实际同一只读 Git 结果、当前输入摘要和精确的结果摘要。复核只决定指定候选对当前分区的适用性。原批准及其历史归属保持；原稿没有原批准时仍需当前正式独审。[[sync-coordinator]] 负责当前阶段门禁、完整验证及交付。
