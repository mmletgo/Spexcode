# Grok Build 原生工作树执行

## raw source

Claude Code 或 ZCode 限流时，用户可以显式选择本机已配置的 Grok Build 接续。Grok Build 在 SpexCode 创建的隔离工作树中完成原任务，沿用正式独审、验收和交付。

## expanded spec

[[llm-manager-host]] 使用 LLM Manager 安装包的 Grok 执行协议。SpexCode 提供绑定工作树的隔离启动描述。Manager 解释 CLI 模型选择，探测实际版本，选择结构化传输并确定原生 Schema 能力。ACP 与流式 JSON 的厂商终态、请求绑定和启动错误由 Manager 解释，返回同一结果结构。每个一次性 Grok 工作树进程照常初始化已配置的 MCP 服务，并在该进程内关闭 stdio MCP 自动重启。传输失败由原会话处理，避免终态后已停止的后代被反复重建。SpexCode 核对精确进程退出、流结束、进程归属和原任务证据。

LLM Manager 为短时原生 streaming-json 执行关闭该子进程的厂商 trace 上传，避免终态后等待上传队列。本机原生会话和结算证据照常保存。ACP 沿用原 trace 设置。

[[llm-manager-host]] 管理的 Grok 工作树在原生 stdout 无原终态、真实非零退出且精确进程组已停止时，只用已排空且未截断的 stderr 诊断中的原 429 或明确额度耗尽，报告可申请正式续路的额度失败。用户取消、其他退出原因和未知停止不触发该分类。

已持久化的 Grok 终态使用同一 Manager 源的离线解析核对完成状态与实际模型，沿已保存的原进程和原请求身份认证。

明确的 `grok:<模型或别名>` 仅进入 [[structured-session-runtime]] 的原生 worktree 路由。`grok:default` 沿用本机配置。每轮记录实际 CLI 版本和模型。选择、输入、预算、独审身份与正式重试规则沿 [[sync-model-selection]]。

编辑任务在本机 CLI 声明支持 ACP stdio 时使用该协议，记录预先生成的 prompt ID，认证同一 session、workspace、prompt 终态和实际用量模型。Manager 在确认该 prompt 终态后关闭 stdin，再观察 stdout 至 EOF。仅原 prompt 的明确限额响应在完整停止和自然退出后可作为正式额度。握手后的缺失终态也须结算原进程。保留仅初始化前和原流式模式的明确启动诊断分类。ACP 初始化响应前已收到真实 EOF 时，沿同一有界观察窗口等待原 CLI 自然退出和 stderr 排空，再判断启动额度。取消或窗口耗尽仍精确清理。

Grok ACP 的内嵌会话通知由 Manager 按原连接和已登记会话区分。只有父会话的文本和精确终态能进入 SpexCode 的正式结果；Manager 处理内嵌会话通知时，原进程归属、退出和独审证据继续按本节点的门禁核对。

一轮只派发一次本机 CLI，使用实际托管工作树和预先绑定的会话 UUID。原生流必须以同一会话、同一工作目录且带唯一原生 request ID 的成功终态结束。终态的 request ID 是 turn 身份。

当 CLI 帮助声明 `--json-schema` 且冻结 schema 的 UTF-8 参数不超过 64 KiB，新派发在既有原生流上启用该选项，并在原生计划记录 `native-schema-v1`。成功输出取自同一终态的原生 `structuredOutput`，并通过冻结 JSON schema。终态缺少该字段时，格式失败保留已结算原请求和最后一段原生文本，供返修时认证未批准草稿。未使用该选项的计划从最后一个工具之后的完整原生文本验证冻结 JSON schema。不同计划共用原生进程、停止与 EOF 证明。

只读任务使用计划模式，并成对关闭进入和退出计划模式的工具。细化与最终候选的两类新只读独审在 Native plan 固定 native-review-table-read-v4，读取 Markdown 表格时先解释表格转义及代码跨度，再比较业务单元格与实现的字面内容。其他新只读派发继续固定 native-file-read-v2。已检出的证据使用原生只读文件工具，避免通用终端和动态工具发现。任务确需读取当前树未检出的历史 Git 对象时才用精确只读 Git 命令。细化独审的节点生命周期及候选代码独审的 priorRefs 可能要求核对当前工作树未检出的历史 Git 对象，因此新独审沿原生只读计划的工具面。独审核对实际候选、相关源码和测试，测试执行由独立验证阶段承担。冷复验按原计划标记重建并核对真实提示摘要，已保存 native-file-read-v2、native-candidate-read-v3 的独审按各自原提示认证。工具权限和必审范围沿原定义。编辑任务在独立工作树中使用明确授权。模型的工作和正常 Git 提交由 [[native-worktree-runtime]] 从实际 Git 对象核验。

在原生停止和进程组结算确证后发布结果。收到绑定原请求的成功终态且 CLI 自然退出为零时，进程组结算与读取 stdout 至 EOF 共用一次独立有界的观察窗口，轮询不延长该窗口。若后代仍占用 stdout，允许沿原进程身份与 receipt 停止已登记后代。收到绑定的成功终态后，在当前退出窗口继续复查进程归属，先给 CLI 五秒完成自己的关闭流程。原 CLI 届时仍在运行才停止已登记且身份仍匹配的后代，包括终态后才启动的后代。同一启动身份至多成功发送一次信号，CLI 自然退出立即结束此等待；本步骤不向 CLI 本身发送信号，接受结果仍须其自然退出为零。只有流实际到达 EOF 且终态后没有其他事件才接受输出。已绑定成功终态但原 CLI 超过退出观察窗口时，结果失败。用单独的有界清理窗口精确停止原进程及其已归属后代，同时确认原 stdout 到达 EOF。停止与 EOF 均确证即返回原退出失败；任一未证实则继续占用容量并保留待恢复。清理期间的退出、EOF 或输出不取得结果发布资格。取消或超时仍阻止结果发布。格式失败可保存绑定同一请求的未批准输出及真实停止后的 Git 草稿供返修。冷读取复验原件，未知启动、未知终态和未知进程组保持待结算，正式停止和回收共用现有控制路径。

新 P0 分析及独审编辑草稿时，Native plan 冻结 native-behavior-evidence-v5。业务前后状态引用任务指定的冻结源码、历史角色及真实路径、符号和断言。分析、独审和续修各自的临时 HEAD、祖先关系及草稿提交用于核对工作树协议；不能代替业务证据。续修将草稿中的临时身份叙述改为冻结业务证据。独审仍逐项检查真实冻结对象，发现错误源码、冻结对象或临时 HEAD 主张时要求修复。旧编辑计划缺该标记时按原提示冷验。独审范围、权限、原 Git 观察及验收沿原规则。

成功终态后的原 CLI 退出逾期单独记录一次父进程诊断。以启动后的单调时间关联终态、截止、定时器触发、退出回调与清理，附截止决策时的子进程退出状态、stdout EOF 及原清理证明状态。日志仅含进程元数据，不载请求、正文或配置，不参与结算、冷读、发布或停止授权。

stdout 在原生终态前结束时保留原失败分类。真实 CLI 退出和同一进程组的停止已确证后，在原生轮次的私有诊断中绑定原 plan、launch、停止记录摘要和真实退出状态。stderr 只记录已观察字节数和摘要、流结束与读取状态、超长行标记，以及从有界完整行识别的明确 HTTP 错误状态和固定的 `usage balance exhausted` 信号。逐段解析行前缀，处理时间随行长度线性增长。固定 CLI 启动错误另可投影为有限诊断类别：严格完整行的 unexpected argument 模板只保留本轮实际 argv 中的选项名；固定完整的 No such file or directory / Permission denied OS 错误模板只保留 ENOENT / EACCES。重复信号合并，未识别行保持仅字节数和摘要。带任意值、路径、URL、认证内容或额外前后缀的行不取得新类别；超长行及其分段均不从截断内容识别。凭据和任意 stderr 原文不落盘。stderr 读取不延长运行或结算窗口。新类别不参与原 HTTP 或明确额度信号判断，也不参与成功、停止或失败分类。诊断供人工检查，不授权重试、换模型、发布或恢复成功结果。

周期观察遇到暂态 pending 时，在 [[native-worktree-runtime]] 的固定观察窗口内继续核验原会话。窗口耗尽或发生非暂态故障时停止原轮。新鲜停止证明成立时登记为失败，停止仍未知时保持待结算。原终态与正式取消优先，恢复不重派任务。

Grok 在成功终态后逾期退出并经清理取得正式失败时，原未公开的 thread/turn 保持缺席。冷态读取未批准的 P0 分析或完整 P1 细化 Git 草稿，以及恢复同一 P1 只读独审，须额外认证 canonical 失败、原工作树、策略和提示、原生计划与 launch/receipt、精确进程已停止、末条停止观察及未形成成功结算。原任务继续失败，不从清理重建 Native 输出。
