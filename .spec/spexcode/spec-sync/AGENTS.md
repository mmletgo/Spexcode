# Spec 同步规范树

本目录保存持续双向同步的产品契约，不保存运行记录。当前待实现节点保持 `status: pending`；只有对应实现和当前版本证据存在后才能更新状态。

- 顶层 `spec.md` 保存九项需求、阶段及验收映射；子节点拥有各自规则，引用上层规则，不复制业务政策。
- `sync-contract-schema/spec.md` 是 sync-v1 固定 Markdown 语法；解析图、状态图、覆盖率与证据是派生产物。
- 每个叶节点最多治理一个现存代码文件；尚无实现时不添加虚构 `code:` 锚点。
- 修改实现时同步对应节点及针对性测试；运行命令下沉到实现目录。

## 同步复验与正式验收

- 集中修复期间按改动影响面选择复验。测试登记、发现和断言绑定改动复验对应入口和用例。共享依赖、夹具、镜像或执行器改动时，复验范围覆盖它们影响的套件。按项目要求执行既有合并门禁。
- 仅续审未通过或受改动影响的分区，影响范围包含受接口或依赖变更波及的分区。候选及相关冻结输入匹配的已通过审查继续有效。结构已通过且仅独审失败时，使用同一 Git 候选续审。候选自身确需修改时，沿原稿只修受影响的分区，再提交独审。
- 集中修复并合入后，从目标项目干净的 `main` 重新冻结。对最终提交完成全树独审、原有完整测试门禁、V1–V4、严格 Git 交付和正式采纳，并核验同步标记。开发期间的预检结果保留为复验证据。
