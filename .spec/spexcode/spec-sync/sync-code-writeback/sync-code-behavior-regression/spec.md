## expanded spec

回归覆盖 [[sync-code-behavior]] 的合法外部变化、独立审查输入、正文与完整测试上下文、稳定冲突/GAP ID、重构无业务授权、文本相容重叠方案、无治理文件上层定位，以及独审遗漏/同会话/未绑定ref/自批政策/弱化验收拒绝。输入和交付实体保持真实来源及共同基线；原source/index不被写。整体运行与产品证据由 [[sync-code-writeback]] 验收。

定向回归覆盖接受前次真实delivery不产生作者授权、其后真实raw差量仍可识别，以及retry范围不能借decision或user:raw授权改无关幂等AC。

真实Git新增治理叶的旧source不含叶、delivery包含叶；未ff采纳时缺失保留交付，实际ff后旧nodeId经公开buildSyncApplicationPlan定位移动/删除，程序逐旧身份退役且已有核心AC保持。最后节点缺失仍有旧raw目标，不以404跳过。此定向用fake native独审，整体真实模型/Docker/交付证据另由上层验收。

定向覆盖真正同raw行重叠的原immutable作者patch与前次A整合、程序choice后缀/作者字节分离、无授权raw改写拒绝；真实raw128种子到具体RULE02+AC02的analyze→derive→parsed evolution闭环，currentB=RULE06不阻A、不授权裸C。独立作者真实删除A与B选择并存仍用userraw退役，不借B来源。

攻击回归复现并拒绝两类raw越权：仅选源码retry的keep裁决改无作者差量raw、真实A/B重叠弱化双方未改权限C；相容A/B合成保持C仍通过。完整P2交付ff接受后只改源码时，changedPaths排除前次已生成Spec/tests且authorChanges为空。

独审同时包含越界checkedPath和具体业务遗漏时仍拒绝批准，但失败诊断保留同次完整finding、证据和反例，并通过下一次冻结repairDiagnostics传给分析与独审；不能只保路径错误而让有限修复预算反复丢失必要验收遗漏。

真实 Git 目录授权新增未跟踪 helper 的完整字节及所在快照进入前置必读/全文清单；旧 HEAD 无该文件不影响读取，删除文件保旧全文，目录、元数据和链接不冒全文或缩小必读集合。漏 helper 的 accept 明确给 missingPaths，并携前轮完整 proposal/未批准 analysis/review 进入新分析及独审；missingPath 和业务 findings 共存不丢。AC 混入未变规则、遗漏目标 affectedId 或不绑定来源给具体诊断，多个 allowed_change 并集不能授权。伪造 diagnostic 或旧 accept 不豁免新摘要/身份/范围门禁，readSet/policy/timeout 仍绑定，诊断与清单共同超 2MiB 时明确失败。
