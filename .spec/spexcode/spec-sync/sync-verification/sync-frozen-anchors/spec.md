# 冻结候选的真实符号锚点验证

## raw source

同步完成前，契约引用的代码来源必须来自实际验证的候选版本，不能被宿主工作区的另一份源码或候选提供的解析器冒充。实际文件没有可引用的声明时，允许引用文件本身。

## expanded spec

本节点承担 [[sync-verification]] 的 V1 代码锚点与来源检查，复用现有 [[code-anchor]] 语言注册表、不可变内容解析缓存和唯一符号判定。输入只有契约图与冻结文件文本；在第一次异步解析前固定查询与文本，不读取当前项目文件、不加载候选依赖、不执行候选代码。

检查 code、带符号的 related 和业务项的 code 来源；related 仍不计实现覆盖。每个声明保留节点、路径、来源位置和符号证据。缺失文件、未知语言、解析器不可用、语法错误、符号消失或重名都阻止该锚点通过，不使用正则回退。类型符号保留既有警告，不伪称业务行为已经验证。

业务项的裸文件路径必须精确命中冻结文件，且可信解析器成功提取零个命名声明。筛选候选文件级来源时复用同一判定，返回排序、去重的精确路径。文件级证据的选择器及符号均为空。若提取出命名声明，V1 以 `anchor-selector-required` 拒绝并将引用绑定到原裸路径。治理和 related 关系的裸路径仍沿各自语义处理。

文件存在、其他契约结构、业务语义和运行行为继续由其所属门禁处理；此检查通过不代表已经同步。

可返修的引用错误保留实际来源角色和精确引用。无效短名可提示同一文件中的真实限定名，提示不取得批准或改变唯一匹配规则。只读候选按实际 owner 交给 Agent 修正，再重新独审和完整执行 V1。
