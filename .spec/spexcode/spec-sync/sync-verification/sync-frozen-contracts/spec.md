# 冻结候选的契约与生成意图门禁

## raw source

实现 Agent 必须服从本轮已冻结的需求和验收；删除契约标记、改写原始需求或换掉验证命令都不能让错误候选免于检查。

## expanded spec

本节点复用 [[sync-contract-schema]] 的解析器、唯一节点身份、完整性和覆盖投影，在冻结文本上执行 [[sync-verification]] 的 V1 与生成约束检查，不从宿主工作区读取另一版本。异步前复制输入文件。结构、代码与测试引用检查包括候选全部声明，符号验证由 [[sync-frozen-anchors]] 承担。

完整候选验证另接收同一 candidate tree 的完整路径清单，复用 [[spec-lint]] 的关系完整性检查，拒绝不存在的 code/related 路径、关系格式错误及违反 one-govern 的元数据。部分正文 readset 不冒充全仓路径清单；合法未读取文件、非文本对象和目录通过清单证明存在。业务 ID 或节点 ID 不能冒充 related 文件路径，该错误在 V1 作为可修复发现返回，不等到严格 Git hook 拒绝后才发现；原 hook、提交 intent 与真实 receipt 门禁保持。

缺失的非治理 related 路径保留结构化引用，供同一真实候选的只读引用返修。治理文件缺失和其它完整性错误继续按原分类阻止通过。

业务 Spec 路径使用 [[plugin-system]] 导出的 PLUGIN_INSTANCE_ROOT 身份统一识别：实例 `.plugins` 子树是工具配置，不作为业务契约节点、意图或治理闭包；当前、历史交付和保护图均采用同一过滤。普通业务子树及本产品 `plugin-system` 系统规格继续参与原有门禁，不能按隐藏目录或名称相似扩大排除范围。

生成基线是本轮用户输入经细化后的冻结契约，不是上一轮旧需求。原始正文逐节点保留；新增节点只接受协调器提供的固定原意或上层引用。已有启用节点不得删除、移走或去掉 schema 来退出本轮检查。所有已接受契约项的稳定 ID 与业务字段以全图核对，业务项允许在保留原节点的情况下移到新叶节点。REQ 的业务内容与 AC 的前置条件、动作、断言、覆盖关系和验证引用不得由实现生成器改弱；AC 的实际测试绑定可补齐。VERIFY 的命令、目录与预算保持冻结；业务说明正文、主流程、状态处置及权威规则也不能由生成器改写。来源和测试符号绑定可以随实际实现更新，不能改变其业务含义。

候选新增 VERIFY 只能引用上层冻结的命令登记；不能自行发明受信命令。用户需求或裁决的合法变化先进入上层细化，成为新的生成基线，不由生成器自批授权。

该门禁报告具体 finding，不颁发同步完成状态。语义正确性、测试断言充分性、GAP 的精确依赖范围、实际运行与版本落盘继续由各自门禁负责。

接受细化前的合法演进由 [[sync-contract-evolution]] 处理授权、节点生命周期与规则变化；本门禁的 before 始终是已接受的新契约，不能沿用旧契约阻止已授权的新 AC，也不能再次授权修改已接受的业务政策。

RULE 的 canonical authority 可随同一稳定规则定义跨叶搬迁；仅在旧新定义各自归属正确时按定位变化比较，其他业务字段和实际约束保持冻结。错误治理归属仍由结构检查和生成意图门禁拒绝。

冻结节点的 raw 只取围栏感知分段结果；没有 raw 段或该段为空时统一为 null，不能把未分段旧 body 认作新的原意。原样 rawless 节点和显式空 raw 的缺席语义一致；非空 raw 的删除、改写或替换仍由原意保护门禁拒绝。

只读写回的未执行覆盖以协调器提供的已审 ID 限定，从实际冻结候选重新推导。候选的新缺口、错误测试绑定、实现锚点及所有其他结构错误继续按原门禁。
