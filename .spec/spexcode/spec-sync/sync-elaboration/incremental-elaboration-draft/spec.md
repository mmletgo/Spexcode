# 原生作者分批写入细化草稿

## raw source

作者可以分批提交规格内容，由程序组装并尽早检查。一个错误批次不应丢失先前合格的工作。程序生成格式、固定身份和可由冻结事实派生的内容。

## expanded spec

普通 Native 完整叶通过只读 Git 阶段配置绑定草稿路径、owner、校验 schema 和冻结输入。CLI 和 stdio MCP 读取同一配置并调用同一个编辑器，使用程序返回的目标及引用。可按冻结 owner、目标、类型与业务键派生新 ID。已有行、授权与 Git 来源沿原 [[sync-elaboration]] 保留。

作者可提交单行、同一流程所需的小批变更或适用性依据。根级适用性按本轮目标汇总，同一批重复提交同一边界会拒绝整批；显式提交一条边界判断可替换从旧稿继承的该边界重复项。写入检查草稿预期摘要、字段 schema、有效目标、行变更约束及当前契约图。新引入的机械引用、归属和演进错误拒绝整批，已写草稿逐字保留；缺少后续义务允许仅作为未完成草稿保存，检查时用原完整结构门给出具体诊断。并行或迟到写入沿同工作树互斥和内容摘要拒绝；只原子更新权属草稿。已带来的格式损坏稿保留在冻结 Git seed，只有显式选择才另起有效草稿。

作者不能填写 `VERIFY` 变更。已有冻结定义沿原归属保留；普通撰写从可信冻结登记为本区生成唯一技术定义，同区各目标引用它。冻结验证退役或更新、节点迁移及专门的只读返修沿原授权协议。跨分区继续由 [[sync-partition-execution]] 投影唯一归属。正式作者返回后从实际 Git 对象核验程序派生的验证登记，也完整重跑原渲染和结构门；独审、整树封口与真实测试继续按原门收口。草稿检查不授予批准。

旧派发及纯父接口保持原协议。新 attempt 首次 P1 登记时冻结编辑器入口，随实际 Git seed 和原生请求摘要保存。临时配置不进入业务规格和交付；冷恢复精确核对旧新各自只读阶段配置，不改写原稿或已通过的独审。[[sync-migrations]]
