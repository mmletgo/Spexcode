# 细化结构化输出与独立审查约束

## raw source

结构化执行必须能程序检查完整候选和独立审查，不能接受一段完成声明作为契约。

## expanded spec

模型临时输出 `elaboration-rows-v1`：目标节点与路径、标题和说明、真实代码/相关绑定、业务解释、各类型的业务行，以及每个适用性边界的依据和影响 ID。全部类型数组均存在，空数组表示无该表；行对象的列直接派生自解析器 `CONTRACT_COLUMNS`，不复制另一份列定义。严格 schema 约束稳定 ID、单一来源、引用数组、布尔值、VERIFY argv 和正整数超时；`STEP.next` 的 END 单值不能混入 ID 列表。有状态流程引用 STATE 结果，不能把同步动作当成无状态能力。

[[elaboration-markdown]] 从这些临时行确定性渲染唯一可编辑的 [[sync-contract-schema]] Markdown。原文、源摘要、输入和候选摘要由程序复制绑定，不交由模型填写。生成行只是一次执行的受检中间产物，不能持久化为第二份权威业务 JSON。返回候选仍为完整 UTF-8 Markdown 文件变更。

权限、写入、异步、网络、并发、回调、重试、取消、幂等和外部副作用都须唯一标明适用或不适用及依据；适用项关联已定义业务 ID。独立评审输出由程序绑定输入及候选摘要，逐项检查全部边界，并把具体发现区分为可修复缺口、缺失业务事实或业务冲突，附证据、影响和裁决问题。

严格 schema 拒绝缺字段、未知字段、错误类型及无效枚举；即使注入执行器也执行相同输出边界检查。任何非接受结论必须有具体发现；接受结论不得仍带未解决发现。
