# 细化结构化输出与独立审查约束

## raw source

结构化执行必须能程序检查完整候选和独立审查，不能接受一段完成声明作为契约。

## expanded spec

生成输出包含输入摘要、完整 Markdown 文件变更及每个适用性边界的依据和影响 ID。每个变更携带节点、仓库相对路径、原内容摘要和完整 UTF-8 正文；不返回另一份可编辑业务 JSON。Markdown 使用 [[sync-contract-schema]] 固定表格；提示的精确表头与分隔模板直接派生自解析器 `CONTRACT_COLUMNS`，不复制另一份列定义。固定标题后只允许空行再紧接表格；说明放在标题之前。分隔行与表头列数一致，`STEP.next` 的 END 单值不能混入 ID 列表。有状态流程引用 STATE 结果，不能把同步动作当成无状态能力。

权限、写入、异步、网络、并发、回调、重试、取消、幂等和外部副作用都须唯一标明适用或不适用及依据；适用项关联已定义业务 ID。独立评审输出绑定输入及候选摘要，逐项检查全部边界，并把具体发现区分为可修复缺口、缺失业务事实或业务冲突，附证据、影响和裁决问题。

严格 schema 拒绝缺字段、未知字段、错误类型及无效枚举；即使注入执行器也执行相同输出边界检查。任何非接受结论必须有具体发现；接受结论不得仍带未解决发现。
