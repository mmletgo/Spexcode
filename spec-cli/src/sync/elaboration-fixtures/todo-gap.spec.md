# 待办事项

## raw source

用户创建待办事项后能够查看结果，系统支持完成和取消操作。

## expanded spec

待办是有状态对象，创建成功进入PENDING，完成或取消后进入对应终态。输入包括创建请求，以及携带待办ID和调用者身份的COMPLETE、CANCEL、VIEW请求。ID唯一，owner固定为创建人，终态不可重新打开。创建失败不产生对象；缺少ID或对象不存在的请求结束于可见错误，不增加对象状态。
登录用户的创建资格与对象初始化分别由独立规则绑定对应裁决。COMPLETE和CANCEL的调用者权限尚未确定，权限分派、条件性转移及相关验收由GAP阻塞；已明确的初始化、生命周期、VIEW和参数错误政策不因权限事实缺失而失效。
演示限于单进程内存中的同步原子操作，无后台worker、网络、外部回调、持久队列、文件、付费或外部副作用，因此异步任务失联、回调身份过期和外部执行结果不可用不适用。取消指待办的CANCEL事件；与完成竞争的两种提交顺序均有明确结果。
创建响应丢失时，在持有当前待办ID的前提下通过VIEW观察结果。事实未提供新建请求去重要求，不承诺重复创建复用对象。无独立重试或恢复能力；重复终态事件按明确的幂等或拒绝规则处理。失败请求不改变对象，随后可以按正确输入查看现有结果。
代码和测试均待实现。依据冻结验证事实，code保持为空；实现映射缺失仍属于待实现证据。验收用例和验证命令仅为未来绑定，没有运行通过的证据。
